# 삼성전자 DS 메모리사업부 S/W개발 실데이터 E2E 검증

이 문서는 1차 검증 당시의 결과와 한계를 보존한다. 현재 버전의 후속 수정·비교 결과는 [확인된 한계 개선 및 비교](samsung-memory-sw-improvements.md)를 참조한다.

검증일: 2026-11-17. AGENTS.md와 references/crawling, references/local-model을 준수했다. 신규 제품 기능은 추가하지 않았으며 기존 분석 처리 수정과 검증 스크립트·회귀 테스트를 추가했다.

## 출처와 테스트 입력

공식 출처: [삼성전자 DS 메모리사업부 S/W개발 직무소개](https://www.samsung-dsrecruit.com/recruits/job_intro/memory/softwareDev.php).

해당 페이지는 상시 직무소개다. 현재 접수 중인 채용공고, 특정 채용 차수의 자격요건·근무지·접수기간·마감일로 해석하지 않았다. 다른 사업부의 같은 이름 직무 페이지와 구분해 memory 경로와 페이지 제목을 확인했다.

사용자 개인의 자기평가·코드는 제공되지 않아 가상 초급 프로필을 사용했다. Python 함수·리스트 기초 실습과 인덱스 오류 수정 경험만 설명하고, 자동 테스트·성능 측정·임베디드·ARM·펌웨어 경험은 없다고 답했다. Python이 포함된 일반 프로그래밍 역량에도 같은 기초 경험을 답하고, 나머지 역량에는 모른다고 명시했다. 이 결과는 실제 사용자의 능력 평가가 아니다.

코드 입력은 서로 다른 함수 이름의 두 코드 쌍이다. 빈 리스트에서는 None을 반환하지만, 비어 있지 않은 리스트에서 길이를 인덱스로 사용해 범위를 벗어나는 오답을 마지막 원소 접근으로 수정했다. 관련 역량 입력은 비워 자동으로 진단 역량 후보와 연결되는지 확인했다. 동일 패턴을 두 코드 쌍으로 관찰한 것은 재현 가능한 반복 집계 테스트이며 독립적인 실제 학습 이력으로 간주하지 않았다.

## 실행 방법과 격리

```powershell
.\venv\Scripts\python.exe scripts/verify_samsung_e2e.py

$env:RUN_SELENIUM_TESTS='1'
.\venv\Scripts\python.exe manage.py test
Remove-Item Env:RUN_SELENIUM_TESTS
```

실제 headless Chrome, Django HTTP 서버, 공식 외부 사이트, 로컬 Ollama의 qwen3:4b-instruct-2507-q4_K_M을 사용한다. 공고·검색·모델·API 응답 대역은 사용하지 않는다. 임시 테스트 DB와 신규 브라우저 세션으로 기존 사용자 DB를 보존한다. 관찰용 서버 래퍼는 실제 응답·시간을 기록하며 내용을 변경하지 않는다.

JSON 응답·소요 시간·자기평가·스크린샷은 `.gitignore`에 포함된 `build/samsung-e2e/`에 보관한다. 전체 외부 원문과 생성 결과를 Git에 추가하지 않는다. 완료 결과는 `results.json`, 초기 분류 문제의 관찰 결과는 `baseline-results.json`, 수정 전 null 수준 오류는 `null-level-failed-results.json`에서 확인할 수 있다.

## 발견한 문제와 수정

1. 초기 Qwen 추출에서 14개 항목 모두 필수로 분류됐다. 업무 구역과 우대 구역에서 인용한 항목도 포함돼 있었다. 원문 섹션과 인용 위치가 명확할 때 Requirements는 필수, Pluses는 우대, Role·Recommended Subject는 구분 없음으로 보정했다. 같은 인용이 서로 다른 구역에 반복되면 임의 보정하지 않는다. 필수·우대가 바뀌면 기본 중요도와 판단 이유도 함께 정리한다.
2. Qwen이 요구 수준을 null로 출력하면서 근거 구분은 inferred로 작성해 502가 반복됐다. 모델 응답에 한해 null 수준은 unknown으로 정리하고 수준 이유·인용을 비운 뒤 Pydantic으로 검증한다. 숫자 수준을 새로 만들지 않는다. 직접 API 입력의 모순, 범위 초과 수준, 잘못된 근거 구분과 원문에 없는 역량 인용은 계속 거절한다.
3. 첫 검증 스크립트가 disabled fieldset의 Selenium is_enabled 반환값을 잘못 해석해 코드 분석 완료 전에 결과를 확인했다. DOM의 실제 disabled 속성을 기다리도록 검증 코드를 수정했다. 이를 앱 장애로 집계하지 않았다.
4. 계획 생성 요청이 5,372토큰으로 실제 Ollama 컨텍스트 4,096토큰을 초과해 HTTP 400을 반환했고 앱에서는 503으로 표시됐다. 계획에 배정된 역량과 관련 실수만 전달하고, 주차별 입력에서 반복되는 기본 문구를 제거했다. 전체 진단·계획 설정·미배정 목록·실수 근거는 DB와 결과에 그대로 유지한다. 서버 모델 설정을 임의로 변경하지 않았다.
5. 기초 수준 질문에서 특정 언어와 실제 SSD 성능 측정을 강제하고, 평가 기준에 수준 이름만 반복하는 응답이 관찰됐다. 질문 프롬프트에 언어 선택 허용, 기초 예제로도 답변 가능, 심화 경험 선택, 역량별 관찰 행동을 담은 평가 기준을 명시했다. 이는 출력 품질 지침이며 의미 정확성을 완전히 보장하는 검증기는 아니다.
6. 후속 질문 묶음에서 모델이 현재 묶음의 역량 ID를 누락·중복해 502가 반복됐다. ID enum과 배열 개수 제한만으로는 중복을 방지하지 못했다. 모델용 질문·채점 스키마를 해당 역량 ID를 필수 키로 하는 객체로 구성하고 서버가 기존 배열 API 형식으로 변환하도록 수정했다. 모델이 내부 값에서 ID를 다시 추측하지 않게 했다. 반환 후 누락·중복 검증은 계속 수행한다. s7 이후 묶음과 누락 응답의 회귀 테스트를 추가했으며, 실패했던 s7~s9 묶음은 실제 Qwen 단독 재검증에서도 통과했다.

생성된 로드맵은 1주차 Python 인덱스 경계값 실습, 2주차 임베디드·ARM 기초, 3주차 요구사항·설계, 4주차 성능 최적화 실습으로 구성됐다. 1주차에는 빈 리스트·원소 한 개의 리스트와 마지막 원소 접근을 검증하는 구체적인 실습이 포함됐다. 계획의 진단 점수는 실수 가산 전후 모두 동일했다.

**내용 품질 판정은 개선 필요다.** 최종 실행에서는 Python 기초 경험을 설명한 일반 프로그래밍 답변까지 0점으로 채점됐다. 질문이 특정 언어·반도체 도메인 경험을 강제해 기초 역량을 과소평가할 수 있다. 앞선 실행에서는 같은 가상 프로필의 해당 항목이 1~2점으로 평가돼, 질문·기준 변화에 따른 점수 안정성도 확인되지 않았다. 또한 최종 완료 기준 문구는 관찰 가능한 검증 조건 대신 주차 제목 수준이었다. 원문·답변 인용의 존재와 수치·DB 일관성을 검증한 것이며, 평가의 타당성과 교육 효과까지 통과한 것으로 보지 않는다. 결과를 좋게 보이게 하려고 점수를 사후 보정하지 않았다.

## 남은 한계

- 기업·사업부·직무 검색 경로는 이번 환경에서 외부 검색 결과를 얻지 못했다. 기존 URL 입력으로 공식 페이지를 수집했다. 자동 검색 성공과 URL 수집 성공을 구분해야 한다.
- Qwen은 실행마다 항목 수와 묶는 방식이 달라졌다. 일반 프로그래밍·임베디드/ARM 등의 복합 항목이므로 특정 언어·운영체제별 숙련도를 독립적으로 평가한 결과가 아니다. 대안으로 나열된 언어를 모두 필수라고 단정하지 않았다.
- 표현만 다른 유사 프로젝트 경험이 별도 항목으로 추출되기도 했다. 현재 중복 제거는 표준 이름·별칭 기준이며 의미상 중복을 완전히 제거하지 못한다. 반대로 같은 근거 문장의 서로 다른 기술을 임의로 합치지는 않았다.
- 원문에 0~5 숙련도 숫자가 없어 숫자 요구 수준은 AI 해석이다. 기초 경험 답변의 점수도 독립적인 실무 검증이나 채용 적합도 점수가 아니다.
- 요구 수준이 없는 항목의 목표는 테스트에서 3으로 선택한다. 이는 학습 목표 입력이며 삼성전자의 요구 수준을 의미하지 않는다.
- 짧은 계획은 전체 역량을 다루지 못한다. 미배정 역량을 확인하고 기간·학습 시간을 조정해야 한다. 인증·프로젝트 경험 등 우대 항목 역시 단순 점수로 실제 성과를 보장할 수 없다.
- 섹션 보정은 인식 가능한 텍스트 제목과 인용 위치에 의존한다. 이미지·PDF·로그인·사이트 구조 변경 및 외부 검색 차단은 별도 한계로 남는다.
- 이번 입력의 컨텍스트 초과는 입력 중복 제거로 수정했지만, 최대 길이 메모·다수 역량·긴 실수 근거가 결합한 모든 입력의 컨텍스트 적합성을 보장하지 않는다. 질문과 평가 기준의 구체성, 설명의 장황함·용어 정확성은 여전히 사람의 검토가 필요하다.
- 질문 지침 보완 후 평가 기준이 구체화된 응답에서도 특정 언어를 가정하거나 초급 질문에 FTL 설계를 요구하는 사례가 남았다. 프롬프트만으로 난이도·언어 선택의 준수를 보장하지 못하므로 점수의 절대 정확성을 검증 완료로 보지 않는다.
- Qwen의 계획 문구가 역량 이름과 일반적인 실습 표현을 반복하는 실행도 관찰됐다. 반복 실수의 연결·가산·회고 근거는 서버에서 보존되지만, 생성된 실습 문구의 구체성과 교육적 효과까지 자동 검증한 것은 아니다.
