# 삼성전자 DS S/W개발: 확인된 한계 개선 및 비교

2026-11-17. [1차 E2E 보고서](samsung-memory-sw-e2e.md)의 수집 실패, 기초 경험 과소평가, 질문별 기준 변화, 추상적인 학습 완료 기준만 개선했다. 기존 화면·API·DB 모델을 유지하며 신규 제품 기능은 추가하지 않았다.

## 수정 범위

### 공식 채용정보 수집

삼성전자 입력 시 검증된 DS 공식 직무목록에서 실제 링크를 읽고 직무·사업부가 일치하는 항목을 우선 제시한다. 직무 URL을 문자열 조합으로 만들거나 다른 사업부의 페이지를 정답으로 대체하지 않는다. 같은 링크는 중복 제거한다. 이 공식 목록을 읽지 못하면 기존 검색 경로를 사용하며 삼성전자 결과는 확인된 공식 도메인으로 제한한다. 그래도 수집하지 못하면 기존 URL·본문 입력을 제공한다.

직무소개는 현재 모집 여부·마감일을 의미하지 않는다는 안내를 결과 목록에 추가했다. 이 개선은 확인된 삼성전자 DS 공식 목록에 적용된다. 임의의 다른 회사의 공식 사이트까지 자동 판별하는 기능을 추가한 것은 아니다.

### 숙련도 진단

기본 질문과 0~5 기준을 서버에서 고정하고 Qwen은 선택적인 심화 상황만 생성한다. 심화 상황은 화면에서 선택 사항으로 구분하고 채점 입력에서 제외한다. 특정 언어·FTL 설계·실제 제품 성능 수치를 기초 채점의 필수 조건으로 요구하지 않는다.

| 상태·수준 | 기준 |
| --- | --- |
| 미평가 (null) | 답변이 비어 있음. 0점으로 치환하지 않음 |
| 0 | 관련 개념·구현의 근거가 없거나 모른다고 명시 |
| 1 | 개념·동작 원리 설명, 구현 경험 없음 |
| 2 | 작은 예제의 직접 구현 과정과 동작 또는 오류 수정 설명 |
| 3 | 프로젝트 적용, 자신의 역할·설계 선택, 정상·실패 검증 |
| 4 | 독립적인 원인 분석·대안 선택·개선 검증 |
| 5 | 설계 비교·측정·최적화 및 재발 방지·확장 설계 |

답변이 있는 항목의 채점은 실제 Qwen이 수행하며 답변에 존재하는 인용을 계속 검증한다. 빈 답변은 기존 서버 처리대로 모델 채점 대상에서 제외하고 null로 남긴다. 목표 직무의 요구 수준, 선택적 고급 사례, 과거 코드 실수로 답변 점수를 낮추거나 올리지 않는다. `작은 구현 경험 → 무조건 2점` 같은 단어 기반 사후 점수 보정은 추가하지 않았다. 기준 2는 자동 테스트나 성능 측정 경험을 필수로 요구하지 않는다.

이미 저장된 완료 진단은 과거 기록으로 보존하며 자동 재채점하지 않는다. 현재 기준으로 평가하려면 새 진단·답변 제출이 필요하다.

### 학습 과제·완료 기준

Qwen 문구로 서버의 기본 과제를 대체하던 처리를 바꿨다. 기본 과제에 Qwen 맞춤 실습을 추가하고, 완료 조건에도 Qwen의 추가 확인 항목을 붙인다. 모델이 제목만 반환해도 다음 최소 기준은 남는다.

- 제출물: 코드 또는 재현 절차와 README.
- 검증: 정상 입력 1개와 경계·실패 입력 1개 이상에서 기대 결과·실제 결과 비교.
- 재현: 실행 명령과 남은 한계 1개 기록.
- 실수 기록이 연결된 과제: 관찰된 실수 유형을 재현하는 입력과 수정 후 결과 기록.

일정·총 시간·필수/우대 순서·실수 가산·진단 점수·미배정 목록은 기존 계산을 사용한다.

기존 사용자 흐름 뒤에 같은 진단의 기초 답변 반복 2회, 개념만 아는 답변, 경험 없음, 빈 답변 대조 검증을 추가했다. 빈 답변 검증에서는 다른 역량 하나에 모른다고 응답해 기존의 전체 공란 제출 방지 조건을 지켰다. 점수의 존재뿐 아니라 정확한 기대 구분을 확인한다.

```powershell
.\venv\Scripts\python.exe scripts/verify_samsung_e2e.py
$env:RUN_SELENIUM_TESTS='1'
.\venv\Scripts\python.exe manage.py test
Remove-Item Env:RUN_SELENIUM_TESTS
```

## 남은 한계

- 초기 실증은 미평가·0·1·2를 다뤘다. 아래 후속 검증에서 제한된 가상 3~5점 답변을 추가했지만, 다른 기술·상충하는 경험·장문 답변까지 정확도가 입증된 것은 아니다.
- Qwen이 만드는 선택적 심화 상황과 추가 실습 설명에는 과도한 난도·부정확한 표현이 남을 수 있다. 기초 채점과 필수 완료 조건에서 그 영향을 분리했지만 의미 정확성 전체를 보장하지 않는다.
- 공식 직무소개는 모집 공고가 아니다. 지원 가능 여부는 실제 채용 공고에서 확인해야 한다. 외부 사이트 구조·접속 제한과 다른 회사의 공식 출처 식별은 한계로 남는다.
- 역량 이름·추출 개수·유사 항목의 의미상 중복 및 요구 수준 추론의 변동성은 이번 범위에서 변경하지 않았다. 실제 숙련도·채용 적합도나 교육 효과를 보장하지 않는다.
- 최대 길이의 입력이 모두 결합했을 때 모델 컨텍스트에 들어가는지까지 보장하지 않는다. 이번 실행에서 컨텍스트 설정이나 모델 자체를 바꾸지 않았다.

증거 JSON·스크린샷은 Git 제외 대상인 `build/samsung-e2e/`에 보관한다. `before-limit-fixes-results.json`이 이전 비교 기준이며 `results.json`이 최신 실행이다. `.gitignore` 대상 파일은 커밋하지 않았다.

## 후속 검증: 3~5점 및 타 기업 공식 직무 (2026-11-17)

관련 진단·수집·분석 코드와 기존 `scripts/verify_diagnosis.py`만 확장했다. 신규 화면·API·DB 모델, 기업별 역량 목록, 답변별 점수 보정, 추출 결과 캐시는 추가하지 않았다. 합성 답변은 검증 입력이며 실제 사용자의 경력이 아니다.

### 변경

- 채점 지침에서 3~5점의 구분과 선택 점수에 맞는 구체적 근거를 명확히 했다. 4점은 독립적인 문제 해결과 한 개선안의 전후 검증이며, 복수 설계 비교·확장 설계를 4점에 요구하지 않는다. 상위 경험이 없다고 충족한 하위 기준을 감점하지 않는다.
- 분석·진단 요청에 입력 내용의 SHA-256으로 계산한 seed를 명시하고 진단 JSON 입력 순서를 고정했다. 이는 추론 조건 통제이며 결과 일치의 보장은 아니다. 특정 답변이나 회사에 기대 결과를 강제로 넣지 않았다.
- Canonical의 문서에 semantic main 요소가 없어 숨겨진 지원 폼·메뉴가 섞이고 30,000자로 잘리는 문제를 수정했다. 일반적인 `#main-content` 영역과 실제 숨김 스타일을 확인하고 폼·iframe·대화상자를 제외한다. 회사별 선택자는 추가하지 않았다. 수정 후 공식 직무 본문은 5,937자로 잘림 없이 수집됐다.

각 원문은 한 번 수집해 같은 문자열로 3회 분석했다. 수정 전후 수집 본문의 SHA-256도 같았다. 순서와 이유 문구의 표현만은 일치 판정에서 제외했다. seed만으로 삼성의 업무·우대 항목 구성 변화는 해결하지 못했다. Canonical의 일치는 수정 전에도 관찰됐으므로 seed의 개선 효과로 주장하지 않는다. 공식 출처 확인과 반복 일치는 내용 해석의 정확성과 별개이며 학위 등 자격 항목과 기술 역량이 섞이는 한계도 남는다.

전체 실모델 검증은 **부분 실패**다. 3~5점 진단은 최종 9/9건 통과했으나 삼성 전체 추출의 반복 일치 조건은 실패했다. 이를 통과로 숨기지 않도록 검증 스크립트는 실패 종료하도록 했다. 중간 재검증에서 점수와 설명이 모순된 사례도 관찰돼 최종 설명 지침을 추가했으며, 최종 9건은 `final-grades.json`으로 별도 보존했다.
